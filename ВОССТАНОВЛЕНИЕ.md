# Аварийная инструкция

Что делать, если сломался компьютер, или если доступ к Claude пропал.

Этот файл лежит в git специально: он доступен с любого компьютера и не зависит от Claude.
Открыть его можно прямо на github.com/idavsego/sonny без установки чего-либо.

---

## Карта активов: что где лежит

| Актив | Где живёт | Переживёт смерть компа? |
|---|---|---|
| Приложение Сонни | `sonny-v9.html` в этом репозитории | **да**, в git |
| База знаний для контента | папка `baza-znaniy/` в этом репозитории | **да**, в git |
| Скиллы «Контент-завода Pro» | локально, `~/.claude/skills/synced/` | **нет** — см. раздел «Профилактика» |
| Данные дневника снов пользователей | хранилище песочницы Claude (`window.storage`) | **нет** — см. сценарий Б |
| Доступ к GitHub | SSH-ключ на компе | ключ не переносят, делают новый |

Правило, на котором всё держится: **пока не сделан `git push`, работы не существует.**

## Сценарий А. Сломался компьютер / переход на новый

### 1. Поставить три программы

- Git — https://git-scm.com
- Obsidian — https://obsidian.md
- Claude Code (если доступен) — https://claude.ai/download

### 2. Забрать репозиторий

```
git clone https://github.com/idavsego/sonny.git
cd sonny
```

Если просит логин — на GitHub нужен Personal Access Token вместо пароля:
GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens →
Generate new token → доступ к репозиторию `sonny` с правом Contents: Read and write.
Токен вставляется в поле пароля. Сохрани его в менеджер паролей, второй раз GitHub его не покажет.

Либо по SSH, если удобнее ключи:

```
ssh-keygen -t ed25519 -C "idavsego@gmail.com"
cat ~/.ssh/id_ed25519.pub
```

Вывод скопировать в GitHub → Settings → SSH and GPG keys → New SSH key. Потом:

```
git clone git@github.com:idavsego/sonny.git
```

### 3. Подключить базу знаний

Obsidian → Open folder as vault → выбрать папку `sonny/baza-znaniy`.
Все заметки и wikilinks на месте.

### 4. Проверить, что всё на месте

```
git log --oneline | head -5
ls baza-znaniy
```

Видишь историю коммитов и папки `1. Контекст` … `4. Производство` — перенос закончен.

### 5. Приложение

`sonny-v9.html` открывается двойным кликом в браузере. Интерфейс, нормы, расчёты работают
локально. Чат и сохранение дневника — нет: они зависят от песочницы Claude (сценарий Б).

## Сценарий Б. Пропал доступ к Claude

Тут три независимые потери, и готовиться к ним надо по-разному.

### Б1. Приложение Сонни перестаёт работать — самое срочное

Сонни сегодня живёт внутри рантайма Claude-артефактов. Две зависимости в коде:

1. `sonny-v9.html:624-642` — хранение через `window.storage.get/set`.
   Это API песочницы Claude, в обычном браузере его нет.
2. `sonny-v9.html:1574-1577` — запрос к `api.anthropic.com` **без API-ключа**.
   Работает только потому, что окружение Claude подставляет авторизацию само.

Значит: пропал Claude — приложение не просто теряет чат, оно перестаёт сохранять дневник.
И данные пользователей, которые лежат в этом хранилище, вытащить будет уже нельзя.

**Что делать (и лучше заранее, а не в день блокировки):**

1. **Снять зависимость от хранилища.** Всего 4 места вызова. Заменить `window.storage`
   на `localStorage` с тем же интерфейсом — приложение начнёт работать в любом браузере
   и на любом хостинге. Это мелкая правка, полчаса работы.

2. **Вынести вызов модели на свой бэкенд.** Ключ нельзя держать в HTML — его увидит любой,
   кто откроет исходник страницы. Нужен минимальный серверный обработчик (на Timeweb, где
   у тебя уже хостинг): страница стучится на свой адрес, сервер добавляет ключ и
   заголовок `anthropic-version: 2023-06-01` и пересылает запрос дальше.
   Побочный плюс: сменить провайдера модели потом можно в одном файле на сервере,
   не трогая приложение.

3. **Проверить доступность провайдера из своего региона.** Anthropic API доступен не везде;
   сервер в России может не иметь к нему доступа. Варианты: держать бэкенд в регионе,
   откуда провайдер доступен, либо взять провайдера, доступного локально. Методика Сонни
   лежит в системном промпте и переносится на любую модель — промпт от провайдера не зависит.

4. **Сделать экспорт данных пользователя** — кнопку «скачать дневник в файл». Тогда любая
   миграция хранилища не стоит людям их истории снов.

### Б2. Не могу кодить с Claude Code

Код в git, он никуда не делся — нужен другой инструмент. Варианты, где можно продолжить
работать с этим же репозиторием:

- **Cursor** или **Windsurf** — редакторы с ИИ, подключаются к разным провайдерам моделей
- **Cline** / **Roo Code** — расширения для VS Code, работают с любым API-ключом
- **GitHub Copilot** — встроен в VS Code
- **Codex CLI** (OpenAI), **Gemini CLI** (Google) — консольные, ближе всего по формату к Claude Code
- **OpenRouter** — один ключ, доступ к десяткам моделей; удобно как страховка от блокировки
  одного провайдера
- **Локальная модель через Ollama** (Qwen, DeepSeek, Llama) — медленнее и слабее,
  но работает без интернета и без подписок вообще

Проект маленький: один HTML-файл и папка markdown-заметок. Его поднимет любой из них.

### Б3. База знаний и скиллы

Тут всё спокойно. База знаний — обычные `.md` файлы: читаются в Obsidian, в блокноте,
на github.com, любым ассистентом. Скиллы «Контент-завода» — тоже markdown с инструкциями.
Любой другой ИИ-ассистент можно попросить: «прочитай файл SKILL.md и работай по нему».
Качество будет зависеть от модели, но сама система не привязана к Claude.

**Единственное условие** — скиллы должны быть у тебя скопированы. Сейчас они лежат только
локально в `~/.claude/skills/synced/`. Если пропадёт доступ к Claude, пропадут и они.

## Профилактика: сделать один раз, сейчас

- [ ] **Сохранить скиллы в git.** Скопировать папку со скиллами «Контент-завода» в репозиторий
      (отдельная папка `skills-backup/`) и запушить. Это материалы курса — восстановить их
      иначе будет нечем.
- [ ] **Второй удалённый репозиторий.** GitHub может ограничить доступ не хуже Claude.
      Завести зеркало на GitLab или Codeberg:
      ```
      git remote add backup git@gitlab.com:<логин>/sonny.git
      git push backup --all
      ```
      Дальше push делать в оба: `git push && git push backup`.
- [ ] **Токен или SSH-ключ GitHub — в менеджер паролей.** Не в заметки на рабочем столе.
- [ ] **Снять зависимость приложения от `window.storage`** (Б1, пункт 1) — пока это полчаса,
      а не аварийная работа под давлением.
- [ ] **Проверить, что бэкап живой:** раз в пару месяцев клонировать репозиторий в отдельную
      папку и убедиться, что база знаний открывается в Obsidian. Непроверенный бэкап —
      это не бэкап.

## Ежедневный ритуал

После каждой рабочей сессии, в папке репозитория:

```
git add -A
git commit -m "что сделал"
git push
```

Три команды. Всё, что до них не доехало, живёт на одном компьютере и исчезнет вместе с ним.
